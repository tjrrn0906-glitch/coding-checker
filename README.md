# 착인 문구 판독기 (완전 무료 · 서버 없는 버전)

**벌크라벨 사진**과 **포장기준서 사진**, 두 장을 찍으면 **휴대폰/PC 브라우저 안에서
바로** 제조번호·제조일자를 읽고(OCR), 포장기준서 속 착인(코딩) 계산 기준을 인식해
단상자·아웃박스에 실제로 찍을 **관리번호 + 사용기한 문구**를 계산해주는 페이지입니다.

서버가 전혀 없습니다 — 사진이 어디로도 전송되지 않고, 이 페이지를 연 사람의
휴대폰/PC가 직접 분석합니다. 그래서 **GitHub Pages 같은 완전 무료 정적 호스팅에
영구적으로** 올릴 수 있고, 서버 비용이나 "잠자기 모드" 문제도 없습니다.

## 사용 흐름

1. **벌크라벨 사진** → 제조번호(자사 로트체계)/제조일자를 자동 인식.
2. **포장기준서 사진** → 착인 계산식이 적힌 단계를 자동 인식해 화면에 글자로 채워줌
   (틀린 부분은 사진과 대조해서 직접 고칠 수 있음).
3. **관리번호 확인/보정** → 기본값은 벌크라벨 제조번호의 검증코드 3자리이며, 고객사가
   별도 대조표(판매문서/배치별 코드표 등)로 관리번호를 지정하는 경우 직접 입력.
4. 포장일 기준 서식인 경우 **포장일자**를 별도로 입력.
5. 아래에 각 단계별로 계산된 **사용기한**과 전면/후면(또는 단일 위치) **착인 문구**가 표시됨.

## 폴더 구성

```
static-app/
  index.html            # 페이지 전체 (디자인 + 화면 로직)
  lot-decode.js          # 자사 로트체계 파싱/검증/사용기한 계산 로직
  ocr-engine.js           # 벌크라벨 사진 전처리 + OCR 실행 로직
  spec-decode.js          # 포장기준서 계산식(착인 기준) 파싱 로직
  spec-ocr-engine.js      # 포장기준서 사진 전처리 + OCR 실행 로직
  vendor/                 # 글자 인식 엔진(Tesseract.js) 파일들 - 그대로 두세요
    tesseract.min.js
    worker.min.js
    tesseract-core-simd.wasm.js
    tesseract-core-simd.wasm
    tessdata/eng.traineddata.gz
    tessdata/kor.traineddata.gz
```

## GitHub Pages에 올리는 법 (한 번만 하면 됨)

1. [github.com](https://github.com) 에서 무료 계정을 만듭니다.
2. 오른쪽 위 **+** 버튼 → **New repository** → 이름은 원하는 대로(예: `coding-checker`) 정하고 **Create repository**.
3. 저장소 페이지에서 **Add file → Upload files** 를 누르고, 이 폴더(`static-app`) **안의 파일과 폴더 전체**를
   끌어다 놓습니다 (index.html, lot-decode.js, ocr-engine.js, spec-decode.js, spec-ocr-engine.js, vendor 폴더까지 전부).
4. 아래 **Commit changes** 버튼을 누릅니다.
5. 저장소 상단 메뉴에서 **Settings → Pages**로 들어갑니다.
6. **Branch**를 `main`, 폴더는 `/ (root)`로 선택하고 **Save**.
7. 1~2분 기다리면 페이지 위쪽에 `https://<계정이름>.github.io/<저장소이름>/` 형태의
   주소가 뜹니다. 이 주소가 현장 직원들과 공유할 최종 URL입니다.

## 지금 자동 인식되는 포장기준서 서식

- **번호 붙은 단계 + 계산식 대괄호/소괄호** 형태 (예: `[벌크제조일기준, 36개월-1일]`),
  전면/후면 각인이 나뉜 경우와 한 곳에 같이 찍는 경우 모두 지원. 계산 기준은
  벌크제조일(라벨에서 자동으로 가져옴) 또는 포장일(직접 입력) 둘 다 지원.
- **코스맥스 "OPERATION BATCH SHEET"** 서식 (라벨 종류별 표 + "N년 후 그 달로 반올림"
  계산 규칙). 일반용/중국용처럼 시장별로 사용기한 표시 자릿수(YYYYMMDD vs YYYYMM)가
  다른 경우도 지원.
- **포장일자 기반 코드 생성** 서식 (예: 뉴스킨 코리아) — 관리번호를 라벨/대조표에서
  가져오는 게 아니라 "제조사코드 2자리 + 포장일자의 연중 며칠째(3자리) + 포장년도
  끝자리(1자리) + 배치번호(1자리)"처럼 직접 계산해서 만드는 방식. 제조사코드는
  문서에서 자동으로 채우고, 배치번호(그날 몇 번째 배치인지)는 사진만으로 알 수 없어
  직접 입력합니다.
- 위 세 서식 외의 특이 서식은 아직 자동 인식하지 않습니다. 포장기준서 인식이 안 되면
  "인식된 글자 확인/직접 수정"란에 계산식을 직접 입력해도 계산은 정상적으로 됩니다.

## 사용 팁

- 처음 열 때 글자인식 엔진(한글 포함, 약 13MB)을 한 번 내려받습니다. 와이파이에서
  한 번 열어두면 그 다음부터는 캐시로 빠르게 열립니다.
- 사진 분석은 여는 사람의 휴대폰이 직접 하기 때문에, 오래된 기종에서는 몇 초 더 걸릴 수
  있습니다.
- 포장기준서는 A4 한 페이지 전체보다, 계산식이 적힌 단계(번호 목록) 부분이 화면에 크게
  나오도록 찍으면 인식이 더 잘 됩니다.

## 알려진 한계

- 아주 흐릿하거나 다른 스티커(판정일자 등)와 겹친 사진은 제조일자를 잘못 추정할 수
  있습니다. 항상 화면에 자동으로 채워진 값을 실제 라벨/포장기준서와 대조해서
  확인해주세요.
- "OTC 표시" 라벨 등 특정 레이아웃에서는 연도 자릿수가 통째로 인식되지 않을 수 있습니다.
- 순번 숫자 "0"이 글자 "O"로 오인식되는 경우가 있습니다.
- 코스맥스 EADEM처럼 관리번호를 판매문서/PO번호별 대조표로 지정하는 경우는 자동으로
  찾아주지 못합니다 — 관리번호 칸에 직접 입력해주세요.
- **계산식이 손으로 취소선 그어진 경우를 구분하지 못합니다.** OCR은 "무슨 글자가
  적혀있는지"만 읽어서, 인쇄된 계산 기준 위에 펜으로 취소선이 그어져 있어도 그
  계산식이 여전히 유효한 것처럼 그대로 계산해버립니다. 이런 문서는 "인식된 글자
  확인/직접 수정"란에서 취소된 줄을 지우고 실제로 유효한 기준으로 고쳐 쓴 뒤
  결과를 확인해주세요.
- 위 세 서식 외의 포장기준서 양식은 아직 자동 인식하지 않습니다(순차 추가 예정).

이 부분들은 실제 사용 사진으로 계속 검증하면서 개선할 예정입니다.
